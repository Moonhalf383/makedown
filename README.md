---

Makefile + Markdown == Markfile + Makedown

Makedown 是一个把工作说明整理成实施计划的命令行工具。你在 Markfile（扩展名为 `.mf`）里写下要完成的目标、每个目标依赖的前置工作，以及完成时要核对的规格。`mkd` 读取这些内容，生成按阶段排列的 Markdown 文档。基础工作排在前面；同一阶段内的目标互不依赖，可以由实施者安排并行处理。这份文档可以交给团队成员，也可以交给协助实施的 Agent。

## 先运行一个示例

项目用 Rust 编写。从仓库根目录运行下面两条命令即可体验，无须提前安装 `mkd`：

```sh
cargo run --quiet --bin mkd -- target greet --root examples/valid/01-single-target/main.mf --check
cargo run --quiet --bin mkd -- target greet --root examples/valid/01-single-target/main.mf -o greeting-plan.md
```

第一条命令检查工作说明，不写文件。第二条命令在仓库根目录生成 `greeting-plan.md`。打开它可以看到 `greet` 目标的工作说明和验收条目。如果不想在仓库里留下输出文件，把最后的路径改为 `/tmp/greeting-plan.md` 即可。

这里的 `target greet` 表示从名为 `greet` 的目标开始生成计划。`--root` 指定该示例项目的入口文件；在自己的项目中，工具会从当前目录向上寻找最近的 `main.mf`。从源码运行时，`cargo run --quiet --bin mkd --` 后面的内容就是传给 `mkd` 的参数；已经有可执行程序时，可以直接写 `mkd target greet ...`。

## 写一份自己的工作说明

如果已安装 `mkd`，在准备存放项目的目录中运行：

```sh
mkd init my-project
cd my-project
mkd build
```

工具会在 `my-project` 中创建入口文件 `main.mf` 和构建设置 `mkd.toml`，再将实施计划写入 `dist/plan.md`。新项目中的目标叫 `start`。直接从源码体验时，可以在本仓库根目录先运行下面的命令；第三行在新建的目录中执行：

```sh
cargo run --quiet --bin mkd -- init my-project
cd my-project
cargo run --quiet --manifest-path ../Cargo.toml --bin mkd -- build
```

完整的初始化方式和配置写法见[项目配置说明](docs/config.md)。

`mkd init` 创建的 `main.mf` 大致如下。`# start` 开始一项名为 `start` 的工作，下面的普通文本说明要做什么，`-` 开头的行描述完成时可核对的结果。文件末尾的 `> start` 将目标声明为可供其他文件引用。

```text
---
# start
描述要完成的工作。
- 明确一条可核验的验收规格。
---
> start
```

可以把示例文字改成自己的工作内容，并为工作添加前置目标。目标之间的关系会决定计划的阶段顺序：先完成依赖项，再实施依赖它们的工作。想看单目标、跨文件协作和并行工作的完整例子，可从[示例项目](examples/README.md)开始浏览。

## 选择构建方式

`mkd target start -o plan.md` 直接为 `start` 目标生成计划，并把文件写入 `plan.md`。需要先检查而暂不写文件时，使用 `mkd target start --check`。这里的 `-o` 指定输出文件；`target` 后还可以写带模块路径的目标名，例如 `catalog::publish`，表示 `catalog` 文件模块中的 `publish` 目标。

若经常生成同一份计划，可以在 `mkd.toml` 里保存目标、输出路径和可选的排版模板。这组设置叫构建配方。`mkd build` 使用默认配方，`mkd build NAME` 使用指定名称的配方；`mkd target` 则直接按命令行给出的目标和输出文件运行。要检查单份文件，可用 `mkd lint main.mf`；要格式化它，可用 `mkd fmt main.mf`。有关命令和路径的具体规则见[项目配置说明](docs/config.md)。

生成的计划有内置 Markdown 排版。想改成自己的任务清单或交接手册，可以阅读[模板写法](docs/templates.md)和[五种中文模板示例](examples/templates/README.md)。使用 Neovim 时，[编辑器配置说明](nvim/README.md)介绍了 `.mf` 和模板文件的高亮、诊断与补全。
